# Доступ к данным: dbapi

`dbapi` — общий интерфейс работы с провайдерами данных NFJS. Он получает соединение с учётом сессии, передаёт параметры адаптеру и управляет транзакцией одиночного вызова. Для PostgreSQL адаптер предоставляет `@nfjs/db-postgres`, а запись через broker подключает `@nfjs/back-dbfw`.

```js
import { dbapi } from '@nfjs/back';
```

## Выбор метода

| Метод | Для чего используется |
| --- | --- |
| `dbapi.query(sql, params, options, control)` | Чтение по SQL с именованными параметрами, фильтрами, сортировкой и диапазоном |
| `dbapi.broker(action, params, options)` | Выполнение зарегистрированной операции записи |
| `dbapi.func(name, params, options)` | Вызов функции провайдера, например функции чтения или вычисления |
| `dbapi.getConnect(context, options)` | Получение соединения для нескольких операций в общей транзакции |
| `dbapi.getProvider(name)` | Получение адаптера по имени; обычно нужен инфраструктурному коду |

Для бизнес-записи используй `broker`. Вызов write-функции через `func` обходит стандартный вход операции и не заменяет broker-контракт.

## query: чтение

```js
const result = await dbapi.query(
  `select id, firstname, lastname
     from company.v4employee
    where birthdate >= :dateFrom`,
  { dateFrom: '1990-01-01' },
  { context },
  { sorts: [{ field: 'lastname', sort: 'asc' }] }
);
```

| Аргумент | Содержание |
| --- | --- |
| `sql` | Текст запроса. Для одиночного чтения передавай строку |
| `params` | Значения параметров `:name`; по умолчанию `{}` |
| `options` | Контекст, провайдер и настройки результата |
| `control` | Фильтры, сортировки, диапазон и позиционирование; передаётся четвёртым аргументом |

В этом примере `dateFrom` ограничивает набор данных по смыслу операции, а `sorts` определяет его порядок. Запрос читает представление `v4employee`, где находятся поля и правила чтения раздела.

Передавай пользовательские значения через `params`. Не собирай SQL строковой интерполяцией значений. Имена объектов и допустимый набор полей определяет серверный контракт.

## Параметры options

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `context` | — | Контекст запроса или выполнения с сессией; передавай явно |
| `provider` | `'default'` | Имя зарегистрированного провайдера или его экземпляр |
| `rowMode` | `'object'` | Строки как объекты; `'array'` возвращает массивы значений |
| `returnFirst` | `false` | Возвращает в `data` первую строку вместо массива |
| `returnRN` | `false` | Добавляет порядковый номер строки `_rn` |
| `signal` | — | `AbortSignal` для отмены запроса, поддержанной адаптером |
| `connectPlace` | — | Метка места вызова для настройки имени соединения |
| `forceCredentials` | `false` | Принудительно использует переданные credentials; требуется специальному инфраструктурному коду |

`context` сохраняет пользователя и организацию при обращении к базе. Провайдер по нему получает credentials и устанавливает сессионные переменные. Параметры отдельного адаптера подробнее описаны в [конфигурации](/nfjs/backend/configuration).

## Результат query

```json
{
  "data": [{ "id": 42, "firstname": "Анна", "lastname": "Смирнова" }],
  "rowMode": "object",
  "metaData": [
    { "name": "id", "dataType": "numb" }
  ]
}
```

`data` содержит строки. `metaData` описывает колонки; конкретные значения типов определяет адаптер. При порционной загрузке результат дополняется `chunk`, `chunk_start` и `chunk_end`. В приведённом JSON метаданные сокращены до одного поля.

Для `pl-dataset` отправляй весь объект результата. Для собственного API можно явно сформировать `{ data: result.data }`, если контракту не нужны метаданные и порционная загрузка.

## broker: зарегистрированная запись

```js
const result = await dbapi.broker(
  'company.employee.add',
  { firstname: 'Анна', lastname: 'Смирнова', gender: 2, birthdate: '1990-04-12' },
  { context }
);
const employeeId = result.data.id;
```

Код операции состоит из кода раздела и действия. В DBFW действие регистрируется в `nfc.unitbps`. Стандартный табличный broker выполняет `add`, `upd`, `del`; при заданной `exec_function` вызывается функция операции. Право на изменение проверяется внутри этого пути выполнения.

```js
await dbapi.broker('company.employee.upd',
  { id: employeeId, lastname: 'Волкова' }, { context });

await dbapi.broker('company.employee.del',
  { id: employeeId }, { context });
```

Обновление получает ключ записи и изменяемые поля. Не подставляй отсутствующим полям `null`, если пользователь их не менял: явный `null` означает запись пустого значения. Удаление может быть отклонено ограничением внешнего ключа — судьбу зависимых данных определяет операция, а не транспорт.

Подробнее: [разделы, операции и права](/nfjs/backend/broker).

## func: функция провайдера

```js
const result = await dbapi.func(
  'nfc.f_session_user', {}, { context }
);
```

PostgreSQL-адаптер получает параметры функции из метаданных. Имя `p_name` в SQL может быть заполнено ключом `name` в `params`; точный набор обязательных аргументов определяется сигнатурой функции. Используй этот метод для чтения и вычислений. Прикладные изменения проходят через зарегистрированную broker-операцию.

## Одна операция и общее соединение

`dbapi.query`, `dbapi.broker` и `dbapi.func` открывают соединение, начинают транзакцию, выполняют вызов, фиксируют результат и освобождают соединение. При исключении выполняется rollback.

Два последовательных `dbapi.broker()` — две отдельные транзакции. Если сохранение родителя и дочерних строк должно быть атомарным, нужен один `Connect`. Его методы описаны в [транзакциях](/nfjs/backend/transactions).

## Частые ошибки

| Симптом | Что проверить |
| --- | --- |
| Чтение не учитывает пользователя | Передан ли исходный `context`; настроены ли сессия и контекст провайдера |
| Сортировка из таблицы не применяется | Передан ли `context.body.control` четвёртым аргументом `query` |
| После ошибки сохранилась часть данных | Не использованы ли несколько независимых `dbapi.broker` вместо одного соединения |
| Broker не находит операцию | Зарегистрированы ли раздел и unitbp; применены ли их `dbsrc/dat` |
| Сохранение получает неожиданный `null` | Не превращает ли форма отсутствующие поля в явно переданный `null` |
