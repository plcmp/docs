# Фильтры, сортировка и диапазон

`control` описывает преобразования над SQL-запросом: отбор, порядок строк и порционную загрузку. PostgreSQL-адаптер применяет их к результату базового запроса. Поля фильтров и сортировок должны присутствовать в его выборке.

```js
const result = await dbapi.query(
  `select id, concat_ws(' ', lastname, firstname) as fio, birthdate
     from company.v4employee`,
  {}, { context }, context.body.control
);
context.send(result);
```

`control` передаётся **четвёртым** аргументом. Если его забыть, запрос выполнится, но изменения сортировки и фильтров на клиенте не повлияют на ответ.

## args и control

| Часть запроса | Назначение | Пример |
| --- | --- | --- |
| `args` | Параметры самой операции | `employeeId`, обязательная дата начала периода |
| `control.filters` | Дополнительный отбор пользователем | Фрагмент имени, отдел, дата |
| `control.sorts` | Порядок строк | Фамилия по возрастанию, затем идентификатор |
| `control.range` | Диапазон для порционной загрузки | Первые 100 строк |

Условия доступа и обязательные ограничения read-контракта должны оставаться в запросе или представлении. Пользовательский `control` уточняет доступную выборку.

## Сортировка

```json
{
  "sorts": [
    { "field": "lastname", "sort": "asc" },
    { "field": "id", "sort": "asc" }
  ]
}
```

Порядок элементов массива задаёт приоритет сортировки. Второе поле делает порядок однозначным, когда фамилии совпадают. Это особенно важно при загрузке данных частями.

`pl-table` меняет `data.sorts` при клике по сортируемому заголовку. Связанный `pl-dataset` наблюдает это изменение и перезапрашивает данные. Backend должен передать `control` провайдеру, чтобы этот запрос получил новый порядок.

## Фильтры

```json
{
  "filters": [
    { "field": "fio", "operator": "like_both", "value": "смирн" },
    { "field": "birthdate", "operator": ">=", "value": "1990-01-01", "cast": "::date" }
  ]
}
```

В примере выбираются сотрудники с фрагментом «смирн» в ФИО и датой рождения не раньше указанной. Фильтры одного массива соединяются через `AND`.

| Свойство фильтра | Назначение |
| --- | --- |
| `field` | Имя поля базовой выборки |
| `operator` | Операция сравнения |
| `value` | Сравниваемое значение |
| `cast` | Преобразование типа или функция над полем и значением |

| Оператор | Поведение |
| --- | --- |
| `=` | Точное равенство |
| `!=` | Неравенство |
| `>` / `>=` | Больше / не меньше |
| `<` / `<=` | Меньше / не больше |
| `like_both` | Поиск фрагмента текста с приведением к нижнему регистру |
| `like` / `ilike` | Сравнение по переданному шаблону `%` и `_` |
| `~` / `~*` | Регулярное выражение PostgreSQL |
| `@>` / `<@` | Операторы содержания для подходящих типов PostgreSQL |

Для проверки `NULL` адаптер поддерживает значения `'()'` и `'!()'` **без** `operator`: соответственно `IS NULL` и `IS NOT NULL`.

`cast: '::date'` приводит поле и параметр к дате. `cast: 'lower'` вызывает функцию `lower` для обеих сторон. Префиксы `left-` и `right-` ограничивают преобразование полем или параметром. Используй варианты, соответствующие типу выбранной колонки.

## Порционная загрузка

```json
{
  "sorts": [{ "field": "id", "sort": "asc" }],
  "range": { "chunk_start": 0, "amount": 100 }
}
```

`chunk_start` — индекс первой строки, начиная с нуля. Вместо `amount` можно указать `chunk_end` — включительную правую границу. `pl-dataset partial-data` формирует диапазоны сам и использует служебные сведения ответа для догрузки.

| Свойство | Назначение |
| --- | --- |
| `range.chunk_start` | Начало запрошенной части |
| `range.chunk_end` | Конец запрошенной части |
| `range.amount` | Размер части, если не задан `chunk_end` |
| `locate.locating` | Включить поиск части, содержащей определённую запись |
| `locate.field` | Поле для поиска записи |
| `locate.value` | Значение этого поля |

Адаптер может включить соседнюю строку для определения продолжения выборки. Поэтому при работе с `pl-dataset` сохраняй метаданные и номера строк ответа; не обрезай его вручную до массива заданной длины.

## Диагностика

| Симптом | Проверка |
| --- | --- |
| Фильтр не действует | Есть ли поле в выборке; переданы ли `filters` и правильный оператор |
| Ошибка преобразования даты | Соответствуют ли значение и `cast` типу PostgreSQL |
| Порядок строк меняется между запросами | Есть ли однозначная сортировка, включая ключ записи |
| Пропадают метаданные подгрузки | Отправляется ли весь результат `dbapi.query` |
| При поиске сохраняются старые условия | Сбрасывает ли форма свой массив фильтров перед новым запросом |
