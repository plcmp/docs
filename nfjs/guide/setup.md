# Подготовка и запуск

Понадобятся Node.js с npm и Docker с Compose. Приложение использует PostgreSQL в отдельном контейнере: порт базы — `54329`, порт HTTP — `4185`.

## 1. Установи зависимости

Исходная модель находится в [Demo-company на GitHub](https://github.com/nf-framework/demo/tree/master/modules/demo-company). Конфигурация и формы шагов руководства — в каталоге `examples/nfjs` [репозитория документации](https://github.com/plcmp/docs). Перейди в этот каталог:

```bash
cd examples/nfjs
npm install
cp config.example.json config.json
```

`@nfjs/dev` устанавливается из [репозитория GitHub](https://github.com/nf-framework/nf-dev): пакет инструментов указан в зависимостях Git-адресом. Для установки также нужен Git.

`modules/demo-company-guide` подключён через npm workspaces. После установки он доступен загрузчику NFJS как пакет `demo-company-guide` в `node_modules`.

## 2. Задай параметры окружения

Создай `.env` в корне приложения:

```dotenv
DB_PASSWORD=замени_паролем_базы
GUIDE_PASSWORD=замени_паролем_пользователя
```

`DB_PASSWORD` используется контейнером PostgreSQL, провайдером и мигратором. `GUIDE_PASSWORD` задаёт пароль пользователя приложения `guide`, которого создаёт первая миграция. Значения должны быть непустыми; выбери их до первого запуска контейнера.

В `config.json` приложение читает провайдер `default`. Для работы браузерных форм используются сессии NFJS, а соединения с PostgreSQL берутся из общего пула. Подробный разбор секций — в [конфигурации приложения](/nfjs/backend/configuration).

## 3. Создай базу и примени исходники

```bash
docker compose up -d
docker compose exec postgres pg_isready -U postgres -d nfjs_guide
```

Дождись готовности PostgreSQL перед миграцией: команда `docker compose exec postgres pg_isready -U postgres -d nfjs_guide` должна сообщить, что сервер принимает соединения. Затем выполни:

```bash
npm run migrate
npm start
```

При первом запуске контейнера `postgres-init.sql` создаёт роль `nfusr`, используемую в правах объектов платформы. Затем мигратор создаёт объекты системных модулей и схемы `company`, загружает метаданные разделов, заводит пользователя `guide` и роль `guide-admin`.

Команда миграции завершается после работы с базой. `npm start` запускает HTTP-сервер и остаётся работающим процессом. Открой [приложение](http://127.0.0.1:4185/ ':ignore'), введи логин `guide` и пароль из `GUIDE_PASSWORD`.

## 4. Разреши работу с прикладными данными

Начальная роль администратора не получает автоматически права на каждый новый прикладной раздел.

1. Открой **«Система → Роли»** и выбери `guide-admin`.
2. В правах разделов найди «Сотрудники» (`company.employee`) и «Контакты сотрудников» (`company.employee_contact`). Разреши просмотр, добавление, изменение и удаление.
3. В доступе к меню разреши «Сотрудники · REST» и «Сотрудники · serverEndpoints» из Demo-company.
4. Для следующих шагов разреши пункты «Модули и разделы», «Объекты базы данных», «Генерация форм» и «Подготовка исходников БД». Идентификаторы форм: `dev.unitlist`, `db-editor.objects`, `dev.generate-form`, `dev.db-source-save`.
5. Обнови страницу приложения, чтобы меню загрузилось заново.

Назначение прав меню открывает ссылку на форму. Для чтения и записи нужны права соответствующих разделов и операций — см. [разделы, операции и права](/nfjs/backend/broker).

## 5. Добавь учебные записи

В другом терминале из того же каталога выполни:

```bash
npm run fill
```

Скрипт входит пользователем `guide`, читает реестр и добавляет через REST шесть сотрудников. Повторный запуск пропускает уже существующие сочетания имени и фамилии; это удобство учебного наполнения, а не правило уникальности сотрудника.

Открой оба реестра Demo-company. В каждом должны появиться Анна Смирнова, Михаил Орлов, Елена Волкова, Денис Ким, Мария Кузнецова и Олег Петров. Порядок зависит от выбранной сортировки.

## Если результат отличается

| Симптом | Что проверить |
| --- | --- |
| Мигратор не соединяется с базой | Готовность PostgreSQL, порт `54329`, одинаковый `DB_PASSWORD` в окружении контейнера и приложения |
| Мигратор сообщает об отсутствии `nfusr` | Инициализация роли выполняется только при создании пустой базы контейнера |
| После входа нет Demo-company | Разрешения меню у роли `guide-admin`, затем обновление страницы |
| Реестр пуст, хотя записи созданы | Право просмотра `company.employee`: его проверяет представление чтения |
| Добавление отклонено | Право операции `company.employee.add`; ошибка приходит из broker |
| Таблицы схемы `company` определены дважды | В приложении одновременно установлены два модуля с исходниками одной схемы. Оставь одного владельца `dbsrc/company` |

Для остановки сервера нажми `Ctrl+C`, контейнера — выполни `docker compose stop`. Обычная остановка сохраняет базу для следующего запуска.
