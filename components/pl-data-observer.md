# pl-data-observer

Отслеживает изменения объекта или коллекции и публикует флаг `isChanged`. Компонент не имеет визуального представления. Он нужен, чтобы показать несохранённые изменения, предложить сохранение или проверить возможность закрытия редактора.

Пакет: `@plcmp/pl-data-observer`.

## Подключение

```js
import '@plcmp/pl-data-observer';
```

## Отслеживание изменений

Измени название, добавь или удали запись — `isChanged` станет `true`. Рядом с редактором показаны текущие данные и журнал `rows._mutations`: `add` — добавлено, `upd` — изменено, `del` — удалено, `touch` — затронуто через вложенную коллекцию.

На исходных данных нажми «Показать touch»: изменится пункт первой записи. Сама запись попадёт в `rows._mutations.touch`, а её пункт — в `rows[0].items._mutations.upd`. Оба журнала видны справа.

## touch: изменения во вложенной коллекции

`touch` отмечает родительскую строку, у которой изменились элементы вложенной коллекции. Например, название записи осталось прежним, но изменилось название её пункта:

```js
this.rows = [
  { id: 1, title: 'План', items: [{ id: 11, title: 'Черновик' }] }
];
this.$.changes.snapshot();

this.set('rows.0.items.0.title', 'Готовый черновик');

// Собственные поля родительской записи не менялись.
this.rows._mutations.upd.length; // 0
this.rows._mutations.touch[0] === this.rows[0]; // true

// Изменённая дочерняя строка находится в журнале своей коллекции.
this.rows[0].items._mutations.upd[0] === this.rows[0].items[0]; // true
```

Добавление или удаление пункта также затрагивает родителя:

```js
this.push('rows.0.items', { id: 12, title: 'Приложение' });
// Новый пункт — в items._mutations.add, родитель — в rows._mutations.touch.

this.splice('rows.0.items', 0, 1);
// Удалённый пункт из снимка — в items._mutations.del.
```

Наблюдатель заполняет `touch` автоматически; отдельного метода `touch()` нет. Не добавляй строки в журнал вручную. Для сохранения одной затронутой строки недостаточно обновить родителя: нужно обработать журнал её вложенной коллекции. Пример передачи таких изменений в `pl-action` — [вложенные данные и paths](/nfjs/nested-changes).

Новый родитель остаётся в `add`: вместе с ним передаётся актуальное содержимое его вложенных данных. После нескольких разных правок существующая строка может одновременно находиться в `upd` и `touch`; эти списки не являются взаимоисключающими статусами.

Изменение поля обычного вложенного объекта без промежуточного массива попадает в `upd` ближайшей строки массива. Для появления `touch` важен переход через вложенную коллекцию, как `items` в примере.

## Снимок и сброс

После получения данных вызови `snapshot()`. Метод запоминает значения полей в `_old`, очищает записи мутаций массивов и устанавливает `isChanged = false`.

```js
await this.$.dataset.execute();
this.$.changes.snapshot();
```

Здесь `dataset` — идентификатор `pl-dataset`, а `changes` — идентификатор наблюдателя, связанного с той же коллекцией. При замене данных загруженной моделью сделай снимок заново.

| Метод | Описание |
| --- | --- |
| `snapshot()` | Принимает текущее `data` за исходное состояние и сбрасывает признаки изменений. |
| `snapshot(object)` | Делает снимок указанного объекта или поддерева. |
| `reset()` | Очищает флаг и записи мутаций в `data`, сохраняя сами значения. |
| `reset(object)` | Очищает записи мутаций указанного объекта или поддерева; сбрасывает общий флаг. |

`reset()` не восстанавливает значения из `_old` и не обновляет снимок. После следующего уведомления старые отличия от снимка могут снова дать `isChanged = true`. Для отмены редактирования восстанови исходную модель отдельно, затем создай снимок.

`snapshot(object)` также сбрасывает общий `isChanged`, даже если вне этого поддерева остались правки. Для независимого сохранения используй наблюдателей над непересекающимися частями данных: [пример с сотрудником и контактами](/nfjs/partial-save). Несколько наблюдателей над одним объектом используют общие `_old` и `_mutations` и не создают независимых снимков.

## Изменение данных

Наблюдатель реагирует на уведомления Polylib. Обновляй коллекцию и её поля через биндинги или методы контекста.

Для редактируемого списка используй `d:repeat="{{rows}}"` вместе с `value="{{row.title}}"`. Двусторонняя связь на повторе возвращает уведомление из контекста строки в родителя; одного двустороннего поля внутри `d:repeat="[[rows]]"` недостаточно.

**Правильно: уведомить о правке поля и состава коллекции**

```js
this.set('rows.0.title', 'Новый заголовок');
this.push('rows', { id: 3, title: 'Новая запись' });
this.splice('rows', 1, 1);
```

**Неправильно: изменить обычные данные без уведомления**

```js
this.rows[0].title = 'Новый заголовок';
this.rows.push({ id: 3, title: 'Новая запись' });
```

Для изменения полей существующих объектов необходим исходный снимок. Добавление и удаление элементов фиксируется как мутация массива. Изменения значения обратно к снимку могут снять признак изменения.

## Свойства и уведомления

| Свойство | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `data` | `Array` | `[]` | Данные для наблюдения. Объявлен тип `Array`, но реализация также обходит обычные объекты. Начальный пустой массив создаётся отдельно для каждого экземпляра. |
| `isChanged` | `Boolean` | `false` | Наличие изменений, вычисляется компонентом. |

```html
<pl-data-observer id="changes" data="{{rows}}" is-changed="{{changed}}"></pl-data-observer>
```

`changed` — объявленное булево свойство родителя. Для получения результата используй биндинг `is-changed="{{changed}}"`. Автоматическое событие свойства называется `isChanged-changed`; оно отличается от преобразуемого имени в `on-*`. Подробнее — [имена событий](/guide/events).

## Ограничения

* Наблюдатель добавляет к данным служебные `_old` и `_mutations`. Не включай их в прикладной DTO без необходимости.
* Это механизм обнаружения изменений, а не история версий и не глубокая копия для отката.
* Не передавай циклические структуры: рекурсивный обход не содержит защиты от циклов.
* Вложенные обычные объекты и массивы обходятся рекурсивно. Изменение содержимого `Date` на месте не создаёт уведомления; заменяй значение через контекст.

См. также: [реактивность](/guide/reactivity), [снимки и журналы](/nfjs/change-tracking), [вложенные данные и paths](/nfjs/nested-changes).

## Стилизация

`pl-data-observer` — невизуальный наблюдатель, скрытый самим компонентом (`display: none`). Его CSS настраивать не нужно; стилизуй видимые поля или контейнеры, которыми управляет форма. Например, переменные темы можно передать контролу через его хост:

```css
pl-input { --pl-content-width: 280px; }
```

CSS формы не проходит сквозь Shadow DOM `pl-input`; для внутренних частей используй опубликованные `part` из документации поля. Общие правила описаны в [руководстве по стилям](/guide/styles).
