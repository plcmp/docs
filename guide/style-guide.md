# Стайлгайд компонентов

Последовательный контракт свойств, явные обновления состояния и чистые функции биндингов упрощают повторное использование компонентов.

## Публичный контракт

Компонент принимает данные через свойства, а состояние, которое пользователь меняет, публикует через собственное свойство и событие `<property>-changed`. Родитель связывает его через `{{...}}`. Командное действие может быть событием, если оно не выражается значением свойства.

`pl-filter` ниже — пример имени собственного компонента с объявленным свойством `value`:

```html
<pl-filter value="{{filter}}"></pl-filter>
```

Назначай объявленное свойство: setter Polylib сам вызовет уведомление об изменении.

**Правильно: присвоить значение объявленному свойству**

```js
this.value = nextValue;
```

**Неправильно: повторно отправить уведомление после setter**

```js
this.value = nextValue;
this.notifyChange({ action: 'upd', path: 'value', value: nextValue });
```

Дублирующее уведомление может повторно запустить observers и биндинги. Для вложенных данных используй `set` или другие методы контекста: [реактивность](/guide/reactivity).

## Короткие правила

* Держи вычислительные функции биндинга чистыми и синхронными. Серверный I/O, запись бизнес-состояния и побочные эффекты запускай отдельным обработчиком.
* Для массивов и объектов применяй `value: () => []` и `value: () => ({})`, чтобы экземпляры не делили одну ссылку.
* Используй `[[...]]` для чтения и `{{...}}` для редактирования. См. [биндинги](/guide/bindings).
* В repeat читай текущую запись из `event.model.<alias>`, а изменения данных проводи через контекст. См. [события](/guide/events) и [шаблоны](/guide/templates).
* Для `d:if` оставляй поведение по умолчанию, если скрытый компонент должен сохранить состояние; `d:restamp` выбирай для намеренного пересоздания.
* В Shadow DOM размещай стили компонента в `static css`, внешнюю оболочку оформляй через `:host`. Токены темы зависят от соглашений проекта: [стили](/guide/styles).
* При переопределении lifecycle вызывай `super.connectedCallback()` и `super.disconnectedCallback()`, снимай собственные внешние подписки. См. [жизненный цикл](/guide/lifecycle).

## Имена и организация кода

* Используй одно имя для файла и тега: `pl-filter.js` регистрирует `pl-filter`. По правилам Custom Elements имя тега должно содержать дефис.
* Объявляй публичные входы и редактируемые значения в `static properties`. Объясняй тип, начальное значение и владельца состояния.
* Разделяй повторно используемый `PlElement` и экран приложения. Сетевые операции и навигацию держи на уровне, который владеет соответствующим сценарием.
* Стили элемента размещай в `static css`, корневую раскладку — на `:host`. Для настройки внешнего вида предоставляй CSS-переменные.
* Подписки на внешние объекты и таймеры освобождай при отключении элемента.

## Пара примеров

**Правильно: вычислить подпись синхронно и без побочных эффектов**

```js
formatLabel(firstName, lastName) {
  return `${firstName} ${lastName}`;
}
```

**Неправильно: запускать запрос из форматтера биндинга**

```js
async formatLabel(firstName, lastName) {
  return await fetch(`/labels?first=${firstName}&last=${lastName}`);
}
```

Функция в биндинге синхронна; возвращаемый Promise не превращается в автоматически ожидаемое значение. Запрос выполняй в явном обработчике или слое интеграции, а результат записывай в реактивное свойство.

См. [модель Polylib](/guide/mental-model), [реактивность](/guide/reactivity), [интеграцию форм](/integration/forms).
