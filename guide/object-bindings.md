# Объекты и биндинги

`[[...]]` задаёт направление уведомлений. Объект или массив передаётся по ссылке: дочерний компонент получает те же данные, что и родитель. Копия, запрет записи и отдельный черновик при этом не создаются.

Поэтому односторонняя связь работает и с объектами. Разница проявляется при записи: замена свойства у потомка и изменение поля общего объекта — разные операции.

## Замена значения и изменение объекта

Редактор `pl-doc-object-editor` из примера ниже объявляет свойство `record`. Родитель передаёт ему свой `profile`:

```html
<pl-doc-object-editor record="[[profile]]"></pl-doc-object-editor>
```

После передачи `editor.record === parent.profile`. При таком биндинге:

| Действие в редакторе | Данные родителя | Уведомление родителю |
| --- | --- | --- |
| `this.record = nextRecord` | Родитель сохраняет прежний объект | Не передаётся |
| `this.set('record.name', 'Мира')` | Поле общего объекта меняется | Не передаётся |
| `this.record.name = 'Мира'` | Поле общего объекта меняется | Не создаётся даже в контексте редактора |

Со строкой, числом или булевым значением потомок может только заменить своё значение. С объектом он дополнительно может изменить содержимое общей ссылки. Массив ведёт себя так же: `push`, `splice` и запись в его элементы меняют общую коллекцию.

При замене объекта только у потомка ссылки расходятся. Следующее уведомление родителя по исходному пути может снова передать его объект редактору. Локальную замену при `[[...]]` не стоит использовать как механизм черновика.

## Данные изменились, интерфейс остался прежним

У `this.set('record.name', 'Мира')` две части: запись в объект и уведомление своего контекста. При `[[profile]]` запись видна через общую ссылку, но уведомление из редактора не поднимается к родителю.

В результате `parent.profile.name` уже равно «Мира», а текст `[[profile.name]]` в шаблоне родителя может показывать «Анна». Подключённый к родителю `pl-data-observer` тоже может сохранить `isChanged = false`. Он реагирует на уведомления; периодического сравнения всей модели у него нет.

Измени имя в обоих редакторах, затем нажми «Прочитать модель». Сравни фактическое значение с текстом родителя и признаком изменений. Кнопка «Изменить у родителя» показывает, что вниз обновление проходит в обоих случаях.

## Редактирование общей модели

Если потомок редактирует состояние родителя, используй двустороннюю связь. Внутри потомка меняй данные через реактивное свойство или методы контекста:

**Правильно: передать уведомление о вложенной правке родителю**

```html
<pl-doc-object-editor record="{{profile}}"></pl-doc-object-editor>
```

```js
// Метод редактора.
this.set('record.name', 'Мира');
```

**Неправильно: считать двусторонний биндинг наблюдателем за любым присваиванием**

```js
this.record.name = 'Мира';
```

Прямая запись во вложенное поле обходит контекст и при `{{...}}`. Это не Proxy над каждым объектом.

Обратный путь должен существовать на каждом уровне. Если форма передаёт объект субформе через `[[...]]`, двусторонний биндинг поля внутри субформы не исправит эту границу. То же относится к [редактируемому `d:repeat`](/guide/templates?id=Редактируемые-строки): для возврата мутаций нужны и `d:repeat="{{rows}}"`, и `value="{{row.name}}"`.

## Независимый черновик

Для редактирования с отменой создай отдельную модель. `[[...]]` и `readonly` у отдельного контрола не изолируют данные от кода компонента.

У обычного DTO без компонентов, функций и служебного состояния наблюдателей можно скопировать весь граф:

```js
beginEdit() {
  this.draft = structuredClone(this.profile);
}

acceptEdit() {
  this.profile = structuredClone(this.draft);
}
```

`profile` и `draft` здесь объявлены в `static properties` как `Object`; редактор получает `draft` через `{{...}}`. Отмена просто отбрасывает черновик. Если данные сохраняются на сервере, заменяй основную модель после успешного ответа, согласно контракту операции.

Поверхностная копия сохраняет вложенные ссылки:

```js
const source = { name: 'Анна', contact: { email: 'anna@example.org' } };
const draft = { ...source };
draft.contact.email = 'new@example.org';
// source.contact.email тоже стало 'new@example.org'.
```

`rows.slice()`, `[...rows]` и `rows.filter(...)` создают новый массив, но сохраняют объекты строк. Такой массив подходит для отдельного порядка или отбора; для независимого редактирования строк нужна копия редактируемых данных.

Не копируй `ControlledArray` как обычный DTO для замены коллекции dataset. У него есть управляющее состояние. Разделяй коллекцию dataset и черновик конкретной записи; подробнее — [работа с коллекциями](/nfjs/datasets).

## Компонент может менять входные записи

В `pl-combobox` поиск по дереву собирает строки из `data` и раскрывает найденных родителей: записывает `_opened = true` и поле из `hasChildProperty`. Это те же объекты, что были переданы компоненту; `data="[[rows]]"` не остановит такие записи.

Если состояние раскрытия дерева не должно попадать в основную модель, подготовь отдельные данные представления до передачи в компонент. Добавление `{{...}}` само по себе не создаст уведомления для прямых присваиваний, выполненных внутри такого компонента.
