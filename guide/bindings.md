# Биндинги

Биндинг связывает выражение контекста с атрибутом, свойством или текстовым узлом шаблона.

## Односторонняя и двусторонняя связь

`[[path]]` передаёт значение от контекста к DOM-узлу или дочернему компоненту. `{{path}}` дополнительно принимает событие `<property>-changed` от целевого узла и передаёт его значение обратно.

```html
<span>[[name]]</span>
<pl-input value="{{name}}"></pl-input>
<pl-input value="[[name]]" readonly></pl-input>
```

Используй `{{...}}`, когда дочерний элемент редактирует переданное состояние и публикует property-changed событие. Для чтения, вычислений и текста выбирай `[[...]]`.

**Правильно: поле редактирует значение через двусторонний биндинг**

```html
<pl-input value="{{name}}"></pl-input>
```

**Неправильно: ожидать возврата редактирования через односторонний биндинг**

```html
<pl-input value="[[name]]"></pl-input>
```

Поле изменяет собственное строковое значение, а односторонняя связь не передаёт его обратно в `name`.

С объектом или массивом есть дополнительная тонкость: `[[...]]` передаёт общую ссылку. Потомок может изменить её содержимое, не отправив уведомление родителю. Данные родителя при этом уже изменятся, а его интерфейс и наблюдатели могут остаться в прежнем состоянии. `[[...]]` не создаёт копию и не запрещает запись. Разбор с примером — [объекты и биндинги](/guide/object-bindings).

Двусторонняя связь не делает произвольный HTML-контрол реактивным сама по себе. Polylib-компонент уведомляет о мутации свойства через событие с `detail.path`, `detail.action` и другими данными изменения. Для собственного `PlElement` достаточно присвоить объявленное свойство — уведомление создаст библиотека.

У нативного `input` нет события `value-changed`. Свяжи значение вниз и обработай браузерный `input`:

```html
<input value="[[name]]" on-input="[[readName]]">
```

```js
readName(event) {
  this.name = event.target.value;
}
```

## Свойство, атрибут и суффикс `$`

Обычный биндинг атрибута в шаблоне сопоставляет его с JavaScript-свойством элемента. Суффикс `$` задаёт именно HTML-атрибут:

```html
<pl-input value="{{name}}"></pl-input>
<div hidden$="[[!visible]]">Содержимое</div>
```

Здесь `value` — свойство; `hidden$` обновляет атрибут `hidden`. В HTML булев атрибут включён своим присутствием: строковое значение `"false"` всё равно считается включённым. При первом создании Polylib разбирает булево свойство из атрибута `"false"` как `false`. Позже динамический `setAttribute('hidden', 'false')` следует обычной семантике HTML и включает атрибут. У Polylib нет `observedAttributes`, поэтому такое изменение атрибута само по себе не обновит свойство и не запустит его observer. Биндинг с `$` устанавливает атрибут для true и удаляет для false.

**Правильно: false удаляет булев атрибут**

```html
<section hidden$="[[!visible]]"></section>
```

**Неправильно: нативный HTML считает атрибут включённым по факту присутствия**

```html
<section hidden="false"></section>
```

## Выражения и функция

Поддержан путь свойства, простое отрицание `[[!flag]]` и вызов функции с аргументами `[[format(first, last)]]`. Это не JavaScript-выражение: тернарный оператор, арифметика, логические цепочки и литералы объектов не вычисляются как JS.

```html
<span>[[fullName(firstName, lastName)]]</span>
<button disabled="[[!ready]]">Продолжить</button>
```

Функция должна быть чистой и синхронной. Для вычислений без побочных эффектов подходит `formatName`; запуск запроса или изменение состояния внутри этой функции вызывает лишнюю работу при обновлении зависимостей.

Перечисляй все реактивные зависимости аргументами. Если `formatName(first)` внутри читает ещё и `this.lastName`, изменение `lastName` не обязано пересчитать биндинг. Передай оба значения: `[[formatName(firstName, lastName)]]`.

В атрибуте используй целый биндинг. Вместо `class="row [[state]]"` вычисли полное значение в helper: `class$="[[rowClass(state)]]"`. Составную строку в тексте можно записать как `Привет, [[name]]`.
