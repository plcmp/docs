# Технические нюансы

Реактивность Polylib связывает пути свойств с уведомлениями и DOM. Совпадение ссылок, изменение данных в памяти и обновление интерфейса — отдельные вещи. Основной пример этого различия разобран в [объектах и биндингах](/guide/object-bindings).

## Один объект по двум путям

Выбранная строка часто хранится отдельно от списка:

```js
this.selected = this.rows[0];
this.set('selected.title', 'Новое название');
```

`selected === rows[0]`, поэтому чтение `rows[0].title` вернёт новое название. Однако мутация имеет путь `selected.title`: биндинг `[[rows.0.title]]` и observer свойства `rows` не получат её автоматически. Библиотека не ищет все ссылки на изменённый объект.

В `pl-grid` это учитывается явно: компонент пересылает вложенные мутации между `selected` и соответствующей строкой `data`. При создании своего компонента с такими связанными свойствами можно использовать тот же приём:

```js
import { PlElement } from 'polylib';
import { normalizePath } from 'polylib/common.js';

class PlSelection extends PlElement {
  static properties = {
    rows: { type: Array, value: () => [] },
    selected: { type: Object, observer: 'selectedChanged' }
  };

  selectedChanged(selected, oldValue, mutation) {
    if (normalizePath(mutation.path).length < 2) return;
    const index = this.rows.indexOf(selected);
    if (index < 0) return;
    this.forwardNotify(mutation, 'selected', `rows.${index}`);
  }
}
```

Этот фрагмент пересылает только вложенные изменения выбранной записи в список. Замена `selected` остаётся сменой выбора. Для правок со стороны списка нужна обратная пересылка; удаление строки и потерю выбора компонент обрабатывает отдельно.

`forwardNotify` меняет префикс пути и сохраняет метку исходной мутации. Она нужна для защиты от повторного прохождения одной правки по связанным контекстам. Не создавай новую мутацию с новой меткой на каждом участке такой связи.

## `oldValue` зависит от глубины изменения

Observer свойства вызывается и при замене всего значения, и при правке вложенного пути. Его первый аргумент — текущее значение объявленного свойства. Второй — предыдущее значение именно изменённого пути.

```js
static properties = {
  profile: {
    type: Object,
    value: () => ({ name: 'Анна' }),
    observer: 'profileChanged'
  }
};

profileChanged(profile, oldValue, mutation) {
  // После set('profile.name', 'Мира'):
  // profile — текущий объект { name: 'Мира' };
  // oldValue — строка 'Анна';
  // mutation.path — 'profile.name'.
}
```

При `this.profile = nextProfile` второй аргумент будет прежним объектом. Это ссылка на объект, а не сохранённая глубокая копия. Для сравнения с исходным состоянием нужен явный снимок; именно поэтому `pl-data-observer` хранит `_old` и получает всю мутацию третьим аргументом. Подробнее — [снимки и изменения](/integration/change-tracking).

## `assign` сообщает о каждом поле отдельно

`assign` последовательно вызывает `set` для переданных полей. Это не пакетное обновление с одним итоговым уведомлением.

```js
this.assign('period', { start: '2026-04-01', end: '2026-04-30' });
```

Сначала observers увидят новый `start` со старым `end`, затем — оба новых значения. Если observer запускает запрос или проверяет целостность периода, промежуточное состояние имеет значение.

Когда состояние должно меняться целиком, сначала собери новое значение, затем присвой объявленному свойству:

```js
this.period = { ...this.period, start: '2026-04-01', end: '2026-04-30' };
```

Родитель получит одну мутацию корневого свойства. Это не обещает одного вызова произвольного вычисляемого helper-а: функция может зависеть сразу от нескольких затронутых путей.

## Повторное присваивание ссылки не обновляет интерфейс

После прямой записи во вложенный объект присваивание той же ссылки не создаёт уведомление:

**Неправильно: пытаться сообщить о правке повторным присваиванием**

```js
this.profile.name = 'Мира';
this.profile = this.profile;
```

**Правильно: изменить значение через контекст с самого начала**

```js
this.set('profile.name', 'Мира');
```

Если прямая запись уже выполнена, `set` того же поля в то же значение тоже сравнит равные значения и не сообщит о правке. Не откладывай уведомление на отдельный «обновляющий» вызов.

Так же работают методы обычного массива: `sort`, `reverse` и прямой `push` не уведомляют контекст. Для обычного массива формы можно присвоить отсортированную копию; для коллекции dataset используй его механизм сортировки. Копия списка при этом по-прежнему содержит прежние объекты строк.

## Массив в `push` считается набором элементов

Метод контекста `push(path, value)` принимает один элемент либо массив элементов:

```js
this.push('rows', { id: 1 });
this.push('rows', [{ id: 2 }, { id: 3 }]);
// В rows находятся три объекта, а не объект и вложенный массив.
```

Для строки матрицы, которая сама является массивом, используй вставку одного значения через `splice`:

```js
const row = ['А', 'Б'];
this.splice('matrix', this.matrix.length, 0, row);
```

`rows` и `matrix` здесь — заранее созданные массивы. Внутри компонентов похожим образом заменяют содержимое коллекции с сохранением её ссылки: `this.splice('rows', 0, this.rows.length, ...nextRows)`. Например, этот приём используется в `pl-dataset` и в отфильтрованном списке `pl-combobox`.

## `d:repeat` сохраняет экземпляры по позиции

При передаче нового массива Polylib переиспользует уже созданные экземпляры строк последовательно. Поле `id` само по себе не становится ключом DOM.

```js
// Был порядок: запись 1, запись 2.
this.rows = [this.rows[1], this.rows[0]];
```

Первый дочерний компонент теперь получает запись 2, но остаётся тем же экземпляром. Его собственный неподвязанный черновик, раскрытое меню или иной локальный флаг могут остаться от записи 1.

Храни состояние, относящееся к записи, в её модели либо явно обновляй его при смене входной записи. Не считай `connectedCallback` инициализацией каждой новой строки данных: при такой замене он не вызывается заново.

Для редактирования полей самой записи связывай их с текущим alias:

```html
<template d:repeat="{{rows}}" d:as="row">
  <pl-input value="{{row.title}}"></pl-input>
</template>
```

Если нужен отдельный локальный черновик, его создание должно зависеть от смены редактируемой записи, а не от каждого вложенного уведомления — иначе правки пользователя могут сбрасываться во время ввода. Удаление и вставка через `splice` создают новые экземпляры для вставленных позиций; это другое поведение, чем присваивание нового массива той же длины.

## Скрытое поле остаётся участником валидации

Если ветка `d:if` уже была создана, переключение условия в `false` без `d:restamp` только скрывает её. Контрол остаётся подключённым, хранит своё значение и `invalid`. Его подписки и код тоже продолжают существовать.

`pl-valid-observer` проверяет `invalid` у элементов своего контейнера и не исключает их только из-за `display: none`. Поэтому ранее созданное пустое обязательное поле может блокировать сохранение после скрытия.

```html
<pl-valid-observer invalid="{{invalid}}"></pl-valid-observer>
<template d:if="[[showDetails]]">
  <pl-input required value="{{details}}"></pl-input>
</template>
```

Выбери поведение по смыслу формы:

* Если скрытые данные по-прежнему сохраняются, их проверка может оставаться обязательной.
* Если раздел временно не участвует в операции, связывай его обязательность и доступность с этим условием. У `pl-input` значение `disabled` исключает поле из `invalid`; `readonly` — нет.
* Если состояние вложенных контролов нужно уничтожить, используй `d:restamp`. Это удаление поддерева с потерей его локального состояния.

Агрегированный `invalid` у `pl-valid-observer` обновляется с задержкой 100 мс. Сразу после `await field.validate()` читай `field.invalid`; не предполагай, что общий флаг формы уже пересчитан. См. [проверку перед запросом](/integration/validation?id=Проверка-непосредственно-перед-запросом).

## Поле класса конфликтует с реактивным свойством

`static properties` уже создаёт accessor экземпляра. В Polylib повторное объявление того же имени полем класса вызывает `TypeError: Cannot redefine property` при создании компонента:

**Неправильно: определить одно свойство двумя способами**

```js
static properties = { title: { type: String, value: '' } };
title = '';
```

**Правильно: задать начальное значение в descriptor**

```js
static properties = { title: { type: String, value: '' } };
```

Позднее присваивание `this.title = value` использует созданный setter и уведомляет контекст. Для внутреннего нереактивного состояния можно использовать отдельное имя поля, например `_requestId = 0`.
